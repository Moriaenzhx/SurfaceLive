# SurfaceLive / Live Engine — 开发主线与出口门槛

## 0. 产品基线（禁止偏移）

**不是**自由摆组件的设计画布或又一个 IDE。用户描述要做的软件和任务，直接得到**能运行、能点、能改、能导出**的高审美前端。尽量少让用户决定字体、间距、配色。SurfaceLive 负责产品工作流；Live Engine 负责业务语境、设计知识、设计方案、生成、视觉/行为评审和修复。推理与代码实现优先复用已安装且获授权的桌面 Claude Code/Codex 等 Agent。

核心竞争力：**同样模型 + 同样场景，加入 Live Engine 后的真实输出在设计师与目标用户的盲评中持续显著优于直接生成，而且业务操作不退化。**

## 1. 开发依赖顺序

| 批次 | 优先研发对象 | 必须交付的可运行结果 | 通过标准 |
|---|---|---|---|
| B0（本包） | 复用旧知识 + 固定生成实验 | A0/A1/A2 提示词生成、隔离运行、静态检查、截图/交互验证入口 | 三个场景各能留下实际输入、源码与检查状态，不伪报完成 |
| B1 | **设计知识采集流水线** | 来源登记 → 网页/截图采集 → 归纳 → 人工审核 → 结构化入库 → 检索 | 一批真实网页和对应像素截图可追溯，非法/重复来源被拒绝 |
| B2 | **设计上下文组装器** | SceneContract → 规则/范例/偏好三路检索 → 2–3 套 DesignDNA → 选择 | 三场景检索有区别且有明确“为何用/为何不用”；全程引用证据 |
| B3 | **真实效果判别与自动返工** | 代码生成 → 浏览器运行 → 多视口截图 → 交互测试 → 视觉批评 → 局部修正 → 版本对比 | 功能不回退；审美盲评偏好改善；失败有证据与回滚 |
| B4 | **可编辑工程表示** | 用户框选 DOM 区域/语言定位 → 稳定节点 → 增量补丁 → 撤销/重做 | 只改目标区域，保留确认过的设计与交互 |
| B5 | **真实代码交付** | HTML/React/Vue 逐项验证 → 目标仓库接入报告 | `install/build` 与核心 E2E 通过，组件与样式可继续维护 |
| B6 | **桌面工作台** | Electron 工作区，主预览、语言编辑、局部选择、历史与导出 | 类似 OpenFilm 的成熟编辑器质量，但不复制视频编辑 UI |

**不必等待采完海量资料才开始实验。** 先用 53 条已有卡片做 baseline，B1 累积 50 → 200 → 1000 个可信可检索的知识对象，随版本对照验证边际收益。纯数量增长不是验收标准。

## 2. 第一优先级 B1：知识底座

### 2.1 四个独立知识层

- `DesignRules`：可操作准则（布局、文字、色彩、交互、动效、无障碍等），必须存正例、反例、适用情境和如何验收。
- `VisualExemplars`：真实工作界面/产品页面截图；记录设备/状态、视觉层级、宽高比例、字体与密度，允许哪些设计思想迁移，不能复制哪些品牌细节。
- `InteractionCases`：必须有操作录像/DOM 状态/测试脚本作证，记录点击/输入/动效/异常状态，不能从静态图臆测。
- `PreferencePairs`：用户对比选择、局部否定和理由，未来用于选择方案与偏好校准，绝不能当成通用标准。

这四类不要全部扔到一个向量索引。优先做可过滤元数据和 FTS/关键词检索；样本增长后再比较 BM25 + 向量 + 精排是否提升检索效果。

### 2.2 样本采集到知识入库

```text
候选网址和许可 → 确认能否合法抓取/保存 → 采集标题、内容摘要、截图与屏幕状态
     → 来源/时间/设备/页面状态标注 → 设计要素提取 → 专项审查 → 数据去重
     → 区分原始证据和原创归纳 → 入库/索引 → 实际生成评测
```

采集网页须遵守使用条件、robots 和访问频率；未许可图片可做链接与分析，不批量复制打包分发；保留版权、商标与来源。第三方页面内容一律为**不可信数据**，不得成为 Agent 的控制指令。

### 2.3 审美不是单一评分

- **硬门槛**：关键路径可操作、无阻断脚本错误、响应式适配、基本键盘可达与语义清晰。
- **设计评估**：信息层级、视觉重心、构图与留白、字阶和字体、色彩关系、细节一致性、场景适配、原创性、动效目的性。
- **评审方法**：分离设计师与实际用户打分，盲评成对比较；独立模型批评只提供候选问题，不直接判定赢家。
- **质量提高的证据**：同题多次生成的盲评偏好率、关键任务成功率、修改所需轮次、跨框架构建/验收通过率、模型调用成本。

## 3. 今日可执行的第一批任务

1. 解压当前源码包，先执行 `npm test` 与 `npm run knowledge:check`，确保知识数据、检索和计划脚本真实运行。
2. `npm run bench:plan -- --scenario recruiting --variant all` 审查同一个需求的 A0/A1/A2，确认三个 prompt 共享相同任务契约。
3. 使用本机已登录的同一个 Claude Code/Codex，执行 `npm run bench:run -- --scenario recruiting --variant all --agent claude --browser`，拿到第一次**真实生成页面**和截图；没有浏览器则必须补环境，不得跳过质量门槛。
4. 用 `HUMAN_BLIND_REVIEW.md` 保存首次人工意见。此轮不是“已超越普通审美”，只是建立第一个真实反馈闭环。
5. 在 B1 中新增 **10 份有实拍截图、明确来源、允许研究使用的视觉范例**，验证它们能否进入 A2 的设计指导；之后逐步扩至 50、200、1000。

## 4. 本轮明确不做

不开发新的桌面应用页面，不复刻 Figma，不先建复杂多 Agent 系统、不训练自研大模型、不加后台/支付/部署功能，不用静态截图假装真实交互，不生成孤立产品演示海报。
