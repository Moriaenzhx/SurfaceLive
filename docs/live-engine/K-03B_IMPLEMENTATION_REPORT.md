## 一条设计原则怎样走到首稿

知时的导演从 `daily-index` 采纳按日期组织时段的构图原则。其引用链是 `LAY-001` 和 `vis-nearby`；后者支持条目与读数相邻。导演随后选择“按日读时段”，把同日与跨日间距、理由展开位置写进契约。编码输入的 SHA-256 以 `dbdb35d1a04065be` 开头，包含四条入选原则、七个状态及 14 个语义 Token。招聘的“名单与证据双栏”采用 `evidence-register`，将证据与当前人选相邻落实为桌面双栏、手机进详情。编码输入 SHA-256 以 `0c7297450ac1637f` 开头。两次均拒绝将步骤向导作为主结构，未选方向仍可单独检查。[知时实发指令](../../runs/K-03B/zhishi-56Umty/attempt/prompt.md) · [招聘实发指令](../../runs/K-03B/recruiting-WjJUpA/attempt/prompt.md) · [入选与未选方案](K-03B_DESIGN_LANGUAGE.md)

## 能力边界

主操作链覆盖被指定为关键状态的业务路径。次要路径可以存在，自动检查覆盖契约实际执行的动作。文本型品牌约束和文化适切性需要结合页面复查；可计算的对比度、字阶、DOM 状态与截图提供不同种类的证据。两个方向给出不同的结构表达，也不能单独证明用户会更喜欢其中一个。审美优势的独立比较留待 K-03E。

状态中的前置条件以业务文字保存。浏览器通过从初始态连续执行、检查禁用状态和验证真实反馈来取证，不能据此证明每一种前置条件组合都正确。已锁定的可计算 Token 在实际组件上接受检查；未锁定样式偏差、首要信息是否露出及自然语言硬约束仍需分别判断。原有修复路径会把失败视口的完整浏览器记录带入纠正指令，多状态场景的修复上下文可能明显增长。本次 E 仅检验真实首稿。

招聘的原始截图暴露了一个 DOM 检查无法发现的问题：移动证据区已经展开，截图却截在正文从透明出现的第一帧。知时则暴露了重复列表中动作 ID 不足以识别某一行的问题。独立 Chrome 回放用可访问名称定位真实时段，并等待可见入场动效完成。同一份招聘源码随后能实际读到简历原文和出处。原始门禁、后续宿主重放及独立业务回放分别归档。[原始证据图](../../runs/K-03B/recruiting-WjJUpA/attempt/evidence/mobile-state-evidence.png) · [稳定帧](../../runs/K-03B/business-recruiting-vkkwg4/mobile-evidence.png) · [独立回放索引](../../runs/K-03B/business-replay-index.json)

最终运行时只比真实生成时多了验收器修正。它用当前状态内的可访问角色和完整名称消除行间歧义；稳定截图等可见有限动画，再等两帧绘制。按原契约、原源码重放，知时两端各 7 个状态动作、招聘两端各 5 个状态动作全部通过。后续真人评审可以直接用稳定帧评价知时的结果态重心，以及招聘桌面与手机的结构转换。[最终宿主门禁](../../runs/K-03B/contract-recheck-srV545/results.json) · [最终桌面回归](../../runs/K-03B/final-regressions-retest-mppagedr/results.json)
