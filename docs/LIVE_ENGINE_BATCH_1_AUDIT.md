# Live Engine 生成链路审计 · Batch 1

审计对象是 SurfaceLive 0.3.0 的 Electron 客户端、该客户端实际加载的引擎模块，以及两个本机 CLI 适配器。2026-11-21 在隔离的作品库验证。当前工程没有 Git 元数据。修改前抽取了 10 个运行文件的 SHA-256，构建目录与本机应用包逐项相符。[原始指纹与场景探针](../runs/design-audit-20261121/before.json)

## 用户提交后发生了什么

1. 输入框提交需求、当前版本、终端、模型、引用和未保存样式。桌面主进程校验参数，创建任务。打开「设计依据」时还会单独调用方向预览，这次预览不代表执行过生成。[输入框](../desktop/ui/studio.js) · [IPC](../desktop/preload.cjs) · [主进程](../desktop/main.mjs)
2. 新作品使用当前需求。修改作品时还会加入旧需求、最近一轮修改和所选版本的三份源码。原版的 `direction` 运行 `detectScene`、`factoryHits` 和 `retrieve(…,6)`，取其中前三条种子规则供检查器展示。生成提示词另行运行 `createDirectorBrief(…,8)`，取八条规则、适用的静态偏好、种子视觉观察和已审核知识卡。两次查询在长修改请求上还可能使用不同的截取文本。[桌面引擎](../desktop/engine.mjs) · [种子检索与 brief](../live-engine/knowledge/src/live-knowledge.ts) · [已审核知识检索](../live-engine/ingestion/retrieval.ts)
3. 宿主把完整提示词交给所选本机 CLI。Codex 通过 stdin 接收提示词，Claude 有附图时使用结构化图文输入。各自返回的四个字段为标题、HTML、CSS 和 JavaScript。引用知识有代码和提示词证据。模型是否遵循某条规则，需要在作品中另外验证。知识库视觉案例进入这一链路的是 ID、源链接和文字观察。用户附加的图片是另一条输入路径。[真实 Agent 桥接与输出校验](../desktop/agent.mjs)
4. 宿主使用隔离的 Electron Chromium 窗口按目标终端、桌面和手机去重检查。原版检查一次初始水平溢出，再对标记的主按钮执行 DOM click，观察反馈文本是否改变。任一检查返回 false 后，原版仍可保存。这个动作不验证遮挡、其他业务路径或审美。保存版本带项目 ID、父版本和三份源码。导出单独复制这三份源码。[浏览器检查](../desktop/preview.mjs) · [版本发布与导出](../desktop/library.mjs)

## 修改前的能力清单

| 能力 | 判定 | 在桌面链路取得的证据 |
| --- | --- | --- |
| 真实生成、修改、版本保存和源码导出 | 已实现 | 主进程直接调用本机 Claude/Codex，成功解析源码后写入版本目录。现有真实 Codex 放映单还保留了点击结果、导出和重新打开的记录。 |
| 知识检索并进入提示词 | 已实现 | 53 条种子规则有 43 个来源，覆盖 15 个类别。另一库已索引 10 个来源、10 条规则和 10 个视觉案例。检索只取与本次输入匹配的子集。 |
| 场景理解 | 部分实现 | 固定词表从五个场景选一项或回退 general。匹配数用来标记强弱，未分别建模人群、任务、文化、复杂度等维度。 |
| 艺术方向选择 | 部分实现 | 提示词要求构想三种方向。没有返回候选、选择理由或权衡的协议，也没有宿主选择阶段。已执行的艺术方向无法从旧记录还原。 |
| 浏览器交互测试 | 部分实现 | 有桌面与手机真实执行和布尔结果。桌面端原来没有逐次自动保存生成页截图，旧实验的截图在另一条链路。手动框选截图属于用户引用。 |
| 视觉评价、同题成对判断、定向返工、关键回归拦截 | 未实现 | 生成后直接检查并提交。没有把生成截图交给视觉模型再修复的调用，保存条件没有约束关键交互必须通过。 |
| 写入用户审美偏好、按适用范围学习 | 未实现 | 六条种子偏好来自静态 JSON。已索引库内 PreferencePair 数为零。作品版本、手动样式和 Agent/主题设置会持久化，但没有采集选择、拒绝、理由和效果的偏好写入链路。 |
| 同模型四场景的匿名比较 | 未实现 | 现有实验 A1 只加场景，A2 加提示词，两者与这次验收定义不同。旧招聘实验有独立复核结果和匿名包，记录显示真人投票待填写。 |

## 本批加入的真实记录

- 每个已受理的生成或手动修改有独立任务 ID 与事件时间。提示词保存为实际传入 CLI 的完整文本，记录 SHA-256 和字节数。规则、来源、视觉案例、静态偏好与该文本由同一次检索产生。另存检查器的方向结果以便发现差异。
- 截图来自执行检查的 Chromium，取于测试点击前。记录 CSS 视口、截图实际像素、初始页面宽度、反馈前后文本、监听到的错误和 PNG 哈希。图片没有生成出来时留下错误。对模型未回报的实际版本、未执行的视觉评审及返工保留空值或明确状态。
- 成功版本的 `design-trace.json`、`prompt.md`、`evidence/` 和源码跟随 `revision.json` 一次性发布到所选作品库的版本目录。失败、取消或未完成的尝试保存在同库的 `.design-traces/<任务 ID>/`。保存位置在提交前不可用时，失败回执尝试写入客户端用户数据的 `failed-design-traces/`。异常退出留下的最后阶段不是终态。每一笔人工修改记录真实父版本与样式变更。旧作品没有回填推测值。
- 在客户端「设置 → 通用」可查作品保存路径。默认 macOS 路径为 `~/Library/Application Support/SurfaceLive/revisions/`。工程导出继续交付独立的 HTML、CSS、JS；完整提示词和内部记录保留在本地作品库。
